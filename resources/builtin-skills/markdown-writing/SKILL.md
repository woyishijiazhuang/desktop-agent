# Markdown 写作规范

撰写或改写 Markdown 文档时遵循以下规范，输出结构清晰、风格统一的文本。

## 何时使用

- 新建或改写 README、技术方案、使用说明等 Markdown 文档
- 把口语化/纯文本内容整理成结构化 Markdown

## 规范要点

1. 标题层级
   - 文档从一级标题开始，标题层级不跳级（H1 → H2 → H3）。
   - 标题使用中文约定：名词短语、不加句号。

2. 正文与列表
   - 段落间用空行分隔；一句话不超过可读长度，长句拆短。
   - 列表使用 `-`；需要强调顺序时用 `1. 2. 3.`。
   - 名词术语首次出现时给出简短说明，之后保持一致叫法。

3. 代码与命令
   - 行内代码、文件路径、命令统一用反引号包裹。
   - 多行代码使用带语言标识的代码块，保持缩进正确。
   - 命令给出所在目录与前置条件，便于直接执行验证。

4. 表格与图表
   - 适合对照展示的内容用 Markdown 表格，表头明确、列对齐。
   - 需可视化趋势/占比时，用 echarts 代码块输出 JSON 配置。

5. 前后一致
   - 全文中英文混排遵循约定（中英文之间保留空格、标点统一）。
   - 结论前置：先给出结论与要点，再展开细节。

## 产出要求

- 先规划文档大纲（小标题），再填充内容，避免流水账。
- 检查最终输出：链接与路径真实有效，代码块语言标识正确，无前后矛盾。
- 完成后向用户简述文档结构与关键决策。
